# BOOKING-FORM-CHANGES — редизайн формы бронирования

Переработана **подача и взаимодействие** формы (`ReservationForm.tsx` +
`PublicHallBookingWidget.tsx` + `globals.css`). **Бэкенд не тронут:** все
`name=`, payload, сетевые вызовы, расчёт цены, машина верификации и обработчик
`submit` — байт-в-байт прежние. Изменены только разметка/классы/стили/порядок
раскрытия и **display-only** производные значения (новых React-состояний нет).
`npm run build` — зелёный.

## Что изменилось по шагам

### 1. Шаги и прогресс
Плоский `<form>` обёрнут (без переноса инпутов) в **степпер** (Когда · Где ·
Контакты) + три карточки-шага `.booking-step` с кружком-номером (Playfair) и
заголовком. Состояния шага — `активный / выполнен (✓) / ждёт` — вычисляются из
существующих переменных:
- «Когда» ✓ ⇔ `!timeError && startTime && endTime`
- «Где» ✓ ⇔ `!hasConfiguredHall || (tableId && !selectionError)`
- «Контакты» ✓ ⇔ `имя && валидный телефон && (верификация если нужна)`
Клик по шагу степпера плавно скроллит к секции (`window.scrollTo`, не
`scrollIntoView`; уважает `prefers-reduced-motion`).

### 2. Карта столов — сердце формы
- Заметная подсказка-чип **«Нажмите на свободный стол, чтобы выбрать»** пока
  стол не выбран; после выбора — **«Стол N выбран ✓»** (зелёный) в сводке стола.
- Мягкий **пульс по свободным столам** (`pulse-hint`, 3 затухающих цикла, не
  бесконечный), пропадает при выборе. Под `prefers-reduced-motion` отключён.
- Тёплая палитра столов уже была внедрена ранее (свободно=белый, выбран=терракота,
  занято=приглушённо, депозит=янтарь) — здесь не менялась.

### 3. Живая сводка + закреплённый CTA
Новая `.booking-summary` (дата · время · гости · стол · депозит, обновляется в
реальном времени) с галочками заполнённости:
- **Десктоп (≥1181px):** форма становится сеткой `1fr 304px`, сводка — липкая
  сбоку.
- **Мобайл/планшет (≤1180px):** сводка — **фикс-панель снизу** с
  `env(safe-area-inset-bottom)`; контент получает нижний отступ.
- Кнопка «Отправить заявку» — в сводке, `type="submit"` (логика submit прежняя).
  Под кнопкой — **причина**, почему пока нельзя отправить («Введите телефон»,
  «Выберите стол», …). При готовности — один мягкий пульс (`bookingCtaReady`).

### 4. Валидация, которая помогает
- Степпер и кружки шагов показывают ✓ по мере заполнения (в реальном времени).
- `phoneError` под телефоном (как было); `timeError`/`selectionError` перенесены
  внутрь своих шагов с `role="alert"`.
- Кнопка disabled теперь покрывает (и **никогда не ослабляет**) исходный гейт:
  `timeError / selectionError / обязательная верификация` + имя + телефон (их и
  так проверял обработчик — стало раньше и виднее). Причина дизейбла — текстом.
- «Комментарий» помечен «необязательно».

### 5. Упрощённое подтверждение телефона
VK ID — крупно и рекомендованно; VK-сообщество и MAX спрятаны под раскрывашку
**«Другой способ подтверждения»** (`<details>`). Логика и состояния
(`pending/confirmed/expired/failed`) не тронуты.

### 6. Микро-взаимодействия
Мягкие переходы (150–220ms) на степпере/шагах/кнопке; пульс CTA при готовности;
пульс свободных столов. Всё под `@media (prefers-reduced-motion: reduce)`.
(Тактильный отклик `navigator.vibrate` — опционально, не добавлял, чтобы не
плодить зависимостей.)

### 7. Мобильная версия
Sticky-CTA снизу + safe-area; поля шагов в один столбец (существующие правила
@640px); карта столов — прежние pan/zoom. Степпер горизонтальный.

## Как проверить
Открыть `/restaurants/<slug>/reserve` (и `/r/<slug>/book`) на **360 / 390 / 768 /
1440** и в VK Mini (`source="vk-mini-app"`):
- **Прогресс:** виден текущий шаг; по мере заполнения шаги получают ✓; клик по
  степперу скроллит к секции.
- **Стол:** до выбора — чип-подсказка + пульс свободных; после — «Стол N выбран ✓».
- **Сводка/CTA:** десктоп — липкая сбоку; мобайл — фикс снизу; кнопка disabled с
  причиной, активируется когда всё готово.
- **Путь без обязательного подтверждения** (`requirePhoneConfirmation=false` или
  VK Mini): форма короткая, «Другой способ» свёрнут, достаточно имени+телефона.
- **Путь с обязательным подтверждением:** кнопка ждёт `verification.confirmed`.
- **С депозитом / без:** строка депозита в сводке и в `.booking-link-box`.
- **Reduced motion:** анимации/пульс отключаются.
- Отправить тестовую бронь — payload, цена и верификация работают как раньше.

## Не менялось (контракт)
`name=` (reservationDate/startTime/endTime/guestsCount/customerName/customerPhone/
fallbackTableId/comment), payload, `/api/...` вызовы, расчёт цены, машина
верификации, `submit()`, success-модалка. Все инпуты остаются смонтированными в
`<form>` (FormData для `fallbackTableId`/`comment` не ломается).
