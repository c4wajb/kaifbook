# GEO-CHANGES — реальная геолокация и расстояние («Рядом»)

Гость может поделиться местоположением и видеть **реальное расстояние** до
ресторанов, а раздел «Рядом» сортируется по близости. Работает уже сейчас —
**28 из 34** активных ресторанов имеют координаты в БД. Геокодер (Яндекс) нужен
только чтобы дозаполнить оставшиеся и новые адреса — он опционален.

## Что добавлено (веб — деплоится как обычно)

- **`lib/geo.ts`** — чистые помощники без сети/ключей: `haversineKm()` (формула
  гаверсинуса), `formatDistance()` («350 м» / «1,2 км»), `distanceLabel()`.
- **`components/location/UserLocationProvider.tsx`** — клиентский контекст +
  хук `useUserLocation()`. Запрашивает координаты **только по действию
  пользователя** (`request()`), кэширует на сессию (`sessionStorage`), мягко
  обрабатывает отказ/недоступность. На вебе — `navigator.geolocation`; в нативе
  (Capacitor) — динамически грузит `@capacitor/geolocation`.
- **`components/restaurant/NearbyRail.tsx`** — реальный раздел «Рядом». Пока нет
  локации — показывает «Популярные» (как раньше) + кнопку «Показать поблизости».
  После согласия — заголовок «Рядом с вами» и сортировка по расстоянию.
- **`RestaurantCard`** — под адресом показывает расстояние (`350 м · ул. …`),
  когда локация известна. Карточки без координат просто не показывают расстояние.
- **Профиль ресторана** (`RestaurantDistance`) — в шапке показывает реальное
  расстояние, если гость уже делился локацией (берёт из того же кэша, без
  повторного запроса); иначе — прежний статичный `distanceText`.

Геолокация не блокирует рендер: страница рисуется сразу, расстояния
«доезжают» после согласия. Ключи геокодера — только на сервере.

## Геокодер (дозаполнение координат) — спящий, нужен ключ

Включается переменной окружения (сервер-онли):

```
YANDEX_GEOCODER_KEY="..."   # https://developer.tech.yandex.ru/services — Geocoder API
```

Без ключа всё ниже — no-op (никаких ошибок, координаты не трогаются):

- **`lib/geocode.ts`** — `geocodeAddress()` (адрес → координаты через Яндекс),
  `geocoderConfigured()`. `import "server-only"` — ключ не попадёт в клиент.
- **Geocode-on-save** (`lib/restaurant-data.ts`) — при сохранении ресторана, если
  ключ задан и координат ещё нет, адрес геокодится автоматически. Существующие
  координаты **не перезаписываются**.
- **Бэкофилл** — `npm run geo:backfill` (`scripts/backfill-coordinates.ts`,
  самодостаточный). Заполняет только пустые координаты, можно гонять повторно;
  `--force` — перегеокодировать все. Сейчас дозаполнит **6** ресторанов без
  координат.

## Нативное приложение (Capacitor)

Приложение грузит живой сайт (`server.url`), поэтому веб-фича доедет и в
приложение — но нужен пересобранный бинарник с плагином и разрешениями.
Проекты `android/`/`ios/` в `.gitignore`, поэтому правки внесены локально; на
машине сборки повторить:

1. `npm install` (ставит `@capacitor/geolocation@^8`).
2. `npm run mobile:sync` (регистрирует плагин; уже выполнено локально — Android +
   iOS/Package.swift).
3. Разрешения (уже добавлены локально):
   - **Android** `android/app/src/main/AndroidManifest.xml`:
     ```xml
     <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
     <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
     ```
   - **iOS** `ios/App/App/Info.plist`:
     ```xml
     <key>NSLocationWhenInUseUsageDescription</key>
     <string>Доступ к геолокации нужен, чтобы показывать ближайшие рестораны и расстояние до них.</string>
     ```

Старые версии приложения без плагина просто не получат расстояние (мягкий
фолбэк) — веб-пользователи получают сразу.

## Как проверить

1. `/restaurants` (десктоп/мобайл): раздел «Популярные» с кнопкой «Показать
   поблизости». Нажать → браузер спросит геолокацию → раздел станет «Рядом с
   вами», карточки отсортируются по расстоянию, под адресом появится «N м/км».
2. Отказать в доступе → раздел остаётся «Популярные» + тихая подсказка, ничего
   не ломается.
3. Профиль ресторана: если уже делились локацией — в шапке реальное расстояние.

## Откат

Презентационная фича + один плагин. Откат — `git revert` коммита; удалить
`@capacitor/geolocation` из `package.json` при необходимости. Колонка
`distanceText` и существующие координаты не трогались.
